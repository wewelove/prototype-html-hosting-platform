# axhub 开发文档

## 1. 项目概述

 axhub 是一个面向产品经理、设计师和产品团队的开源原型资产托管平台。它的核心目标是将 Vibe Coding（自然语言协同编程）时代产生的大量 HTML 原型、AI 生成页面和可交互演示转化为可持续管理的团队资产。

### 核心价值

- **统一管理 Vibe 产物**：集中保存 AI IDE、代码智能体和各类原型工具生成的 HTML 产物
- **兼容传统 Axure 工作流**：支持上传单 HTML、ZIP、RAR 或项目文件夹
- **让评宾链接长期稳定**：原型更新后访问入口保持不变，减少沟通成本
- **控制分享边界**：可开启或关闭分享、设置截止时间和访问密码
- **沉淀团队知识资产**：个人原型可在部门内共享，也可进入公开广场
- **具备基础治理能力**：提供部门、人员、角色、业务分类、存储配额、访问量和登录日志管理

### 目标用户

- 产品经理
- 设计师
- 产品团队
- 开发者

## 2. 技术栈

### 前端

- **Next.js 16** - React 框架，用于管理端、原型访问页和服务端 API
- **React 19** - UI 组件库
- **TypeScript** - 类型安全
- **Lucide-react** - 图标库

### 后端

- **Node.js 24** - 内置 `node:sqlite` 模块，无需额外数据库驱动
- **SQLite** - 单文件数据库，存储账号、部门、权限、原型元数据、访问量和日志
- **Next.js API Routes** - RESTful API 接口

### 部署

- **Docker Compose** - 一键启动应用，无需额外数据库容器
- **数据卷** - SQLite 数据库文件、HTML 原型文件、静态资源和 WebP 首页截图持久化存储

### 核心依赖

- `@next/env` - Next.js 环境变量管理
- `bcryptjs` - 密码哈希
- `date-fns` - 日期处理
- `jose` - JWT 处理
- `jszip` - ZIP 文件处理
- `lucide-react` - 图标
- `nanoid` - 唯一ID生成
- `puppeteer-core` - 浏览器自动化，用于生成原型首页截图
- `react` 和 `react-dom` - UI 运行时
- `zod` - Schema 验证
- `@playwright/test` - E2E 测试
- `vitest` - 单元测试运行器

### 开发工具

- **ESLint** - 代码规范检查
- **Prettier** - 代码格式化
- **TypeScript** - 类型检查
- **Vitest** - 单元测试运行器
- **Playwright** - 端到端测试

## 4. 架构概览

### 4.1 数据流架构

```
用户浏览器
    │
    └── Next.js 16 + React 19
        │
        ├─ API Routes (RESTful)
        │   └── Next.js Server Components
        │       ├─ Auth (Session JWT)
        │       ├─ Project CRUD
        │       ├─ Upload/Download
        │       ├─ Share Management
        │       └─ Admin Operations
        │
        └─ SQLite (node:sqlite 内置)
            └── 单文件数据库
                └── 持久化数据卷 (axhub)
                    ├── 数据库文件
                    ├── HTML 原型文件
                    ├── 静态资源 (CSS/JS/Images)
                    └── WebP 首页截图
```

### 4.2 核心数据模型

#### 用户与认证
- **用户表**: 账号(唯一)、密码哈希、姓名、部门关联、角色(user/admin/super_admin)、状态(active/disabled)、配额
- **会话**: JWT 签名的 cookie，包含 userId 和 sessionVersion
- **权限模型**: 超级管理员 > 管理员 > 普通用户 三级角色

#### 原型管理
- **项目表**: 公共码、分享码、名称、所有者、部门、分类、HTML路径、文件大小、来源类型、公开状态、分享配置、访问统计
- **分组**: 树形结构，归属于用户所有
- **分类**: 业务分类，由超级管理员维护
- **访问记录**: project_visits 表记录 PV/UV

#### 权限控制
- **决策流程**: `decideProjectAccess()` 函数根据路由类型(公开/分享)决定是否允许访问
- **部门范围**: `getAllowedDepartmentIds()` 计算用户可访问的部门集合
- **管理权限**: `canManageProject()` 检查是否有编辑权限

### 4.3 存储架构

```
数据卷 axhub/
├── sqlite/
│   └── prototype-hub.sqlite3 (或自定义路径 via DATABASE_FILE)
├── prototypes/
│   └── {ownerId}/
│       └── {projectId}-{nanoid(8)}.html
│           └── 关联资源 (CSS/JS/Images)
├── previews/
│   └── {ownerId}/
│       └── {projectId}-{nanoid(8)}.webp (自动生成的首页截图)
└── backups/ (云端自行配置)
```

### 4.4 关键工作流

1. **原型上传**
   - 用户上传 HTML、ZIP、RAR 或项目文件夹
   - `prototype-upload.ts` 解析并验证文件
   - `file-storage.ts` 存储到数据卷
   - `db.ts` 记录元数据到 SQLite
   - `capture-preview.ts` 生成 WebP 预览图 (使用 Puppeteer)

2. **原型访问**
   - `/project/{code}` - 公开访问或owner访问
   - `/share/{code}` - 分享链接访问（含密码验证）
   - API `/api/projects/{id}/preview` - 获取预览信息
   - API `/api/mock-preview/{id}` - 生成预览截图

3. **分享管理**
   - 生成带加密密码的分享链接
   - JWT 签名的分享授权 token
   - 访问密码尝试次数限制 (15分钟窗口，10次失败锁定)
   - 分享过期时间控制

4. **权限管理**
   - 部门树结构遍历
   - 基于角色的访问控制 (RBAC)
   - 部门范围内的资源管理
   - 超级管理员全局管理权限

## 5. 核心模块详解

### 5.1 认证与会话 (src/lib/auth.ts)

- **演示模式**: 无需数据库，通过 cookie 存储 demo 会话
- **生产模式**: JWT 签名的 session cookie
- **Cookie 配置**: httpOnly, secure (HTTPS), sameSite=lax, 12小时过期
- **会话刷新**: 密码重置时自动递增 session_version

### 5.2 数据库层 (src/lib/db.ts)

- **单连接模式**: 热更新时复用连接
- **WAL 模式**: 允许读写并行
- **事务串行化**: 防止写入冲突
- **自定义函数**: gen_random_uuid(), now()
- **错误处理**: unique constraint 检测

### 5.3 存储预算 (src/lib/storage-budget.ts)

- **计算模式**: `calculatePlatformStorageBudget()`
- **组成部分**:
  - prototypeUsedBytes: 原型文件占用
  - diskTotalBytes: 磁盘总容量
  - diskUsedBytes: 磁盘已用
  - systemAndOtherUsedBytes: 系统+其他占用
  - reserveRatio: 预留比例 (默认 20%)
  - reserveBytes: 预留字节
  - safeCapacityBytes: 安全容量
  - uploadAvailableBytes: 可上传字节
- **上传限制**: 防止磁盘满盘导致服务不可用

### 5.4 原型上传 (src/lib/prototype-upload.ts)

- **支持格式**: HTML, ZIP, RAR, 项目文件夹
- **验证**: 检查 index.html 或 preview.html 入口
- **ZIP/RAR 解压**: 使用 jszip 和 node-unrar-js
- **路径安全**: 过滤非法路径 (.., :, __macosx 等)
- **入口文件**: 自动查找项目根目录的 index.html/preview.html

### 5.5 预览截图生成 (src/lib/capture-preview.ts)

- **技术栈**: Puppeteer-core
- **流程**: 启动临时 HTTP 服务 → 加载页面 → 截图 → 保存 WebP
- **演示模式**: 使用 demoStore 中的 HTML 内容
- **错误处理**: 超时重试，失败标记
- **缓存**: 通过 captureQueue 串行执行，防止并发过载

### 5.6 访问权限 (src/lib/access-policy.ts)

- **路由类型**: "public" (公开广场) / "share" (分享链接)
- **决策因子**:
  - 是否登录
  - 是否为原型所有者
  - 部门权限范围
  - 原型是否公开
  - 分享是否开启
  - 分享是否过期
  - 分享是否设置密码
- **返回结果**: `AccessDecision` 包含 `allowed`、`needsPassword`、`reason`

### 5.7 权限检查 (src/lib/project-permission.ts)

- `canManageProject()`: 检查管理权限 (所有者或部门管理员)
- `canViewProject()`: 检查查看权限
- `canDownloadProject()`: 检查下载权限 (与管理权限相同)

### 5.8 分享系统 (src/lib/share-session.ts)

- **加密**: AES-256-GCM 加密分享密码
- **授权 token**: JWT 签名，包含 projectId, shareVersion, visitorId
- ** cookie**: `prototype_share_{projectId}` 存储授权信息
- **访问流程**: cookie 中的 token → verifyShareGrant → 决策

### 5.9 部门权限范围 (src/lib/department-scope.ts)

- **用户角色**: 
  - user: 仅自己的部门
  - admin: 所管理部门 + 下属部门
  - super_admin: 所有部门
- **部门树**: `descendants()` 计算所有子部门
- **行政范围**: `admin_department_scopes` 表 维护管理员管辖的部门

## 7. 常见问题与注意事项

### 7.1 环境变量

| 变量 | 说明 | 默认/示例 |
|------|------|-----------|
| `DATABASE_FILE` | SQLite 数据库路径 | `/data/axhub.sqlite3` |
| `DATA_DIR` | 数据目录基路径 | `.data` |
| `NEXT_PUBLIC_BASE_PATH` | 应用基路径 | `/manage` |
| `SESSION_SIGNING_SECRET` | 会话签名密钥 | 32+ random chars |
| `SHARE_PASSWORD_ENCRYPTION_KEY` | 分享密码加密密钥 | 32+ random chars (≠ session key) |
| `COOKIE_SECURE` | Cookie 是否设置 Secure flag | `false` (HTTP), `true` (HTTPS) |
| `BOOTSTRAP_SUPER_ADMIN_PASSWORD` | 首次启动超级管理员密码 | ≥ 8 位 |
| `DEMO_MODE` | 是否启用演示模式 | `false` (生产) |

### 7.2 部署注意事项

1. **数据备份**: SQLite 数据库文件 + 上传目录 + 预览图构成完整数据，建议定期快照
2. **环境变量安全**: `.env` 不得提交到 Git，部署时自行配置
3. **磁盘空间**: 建议预留 20% 磁盘空间给系统和 SQLite ( via STORAGE_RESERVE_RATIO)
4. **HTTPS**: 生产环境必须配置 HTTPS，否则 Session Cookie 被浏览器拒绝
5. **容器资源**: 最少 2核 CPU、4GB 内存，磁盘按原型规模评估

### 7.3 开发常见坑

1. **路径 basePath**: `NEXT_PUBLIC_BASE_PATH` 在构建时和运行时必须保持一致
2. **SQLite 并发**: 单写通道，事务期间其他请求排队
3. **演示模式 vs 生产模式**: 代码中大量 `isDemoMode` 分支，测试时需注意环境变量
4. **上传预览图**: 需要 Chromium/Chrome 可执行文件，Docker 部署需安装
5. **ZIP/RAR 解压**: 依赖 node-unrar-js 的 WASM 模块，首次加载有延迟

### 7.4 性能考量

- **首页预览图**: 生成成本较高，通过队列串行执行，结果缓存
- **数据库查询**: WAL 模式 + 异步请求队列，避免写入阻塞读取
- **存储预警**: 达到安全阈值后拒绝上传，避免磁盘满盘
- **CDN/静态资源**: 原型文件直接从数据卷提供，无额外CDN成本

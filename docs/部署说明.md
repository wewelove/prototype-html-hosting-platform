# 部署说明

## 部署目标

在内网服务器上以单容器方式运行原型托管平台，数据全部落在本地数据卷，不依赖外部数据库或云服务。

## 环境要求

- Linux 服务器（Ubuntu 22.04 及以上），或任意可运行 Docker 的 x86_64 / arm64 主机
- Docker Engine 与 Docker Compose 插件
- 建议最少 2 核 CPU、4GB 内存；磁盘按原型文件规模评估

## 配置步骤

1. 将代码放入服务器独立目录。
2. 参考 `.env.example` 创建 `.env`。
3. 为以下字段生成互不相同的新值（`openssl rand -base64 32`）：
   - `SESSION_SIGNING_SECRET`（至少 32 字符）
   - `SHARE_PASSWORD_ENCRYPTION_KEY`（至少 32 字符，与会话密钥不同）
   - `BOOTSTRAP_SUPER_ADMIN_PASSWORD`（至少 8 字符）
4. 设置 `NEXT_PUBLIC_BASE_URL` 为内网实际访问地址，例如 `http://192.168.1.100:3000`（本地开发的地址覆盖见下文「本地开发与部署环境的地址配置」）。
5. 构建镜像：

```bash
docker build -t axhub:latest .
```

6. 启动服务：

```bash
docker compose up -d
```

7. 检查健康状态：

```bash
docker compose ps
curl --fail http://localhost:3000/manage/api/health
```

容器首次启动会自动执行数据库迁移与超级管理员初始化（已有用户时自动跳过）。

## 访问地址

| 用途 | 地址 |
| --- | --- |
| 管理端 | `http://服务器IP:3000/manage` |
| 公开原型 | `http://服务器IP:3000/manage/project/{code}` |
| 分享原型 | `http://服务器IP:3000/manage/share/{code}` |
| 健康检查 | `http://服务器IP:3000/manage/api/health` |

## 数据边界

- 数据卷 `axhub` 挂载到容器 `/data`，包含 SQLite 数据库、原型文件、静态资源与截图。
- 如需保留数据，使用 `docker volume` 常规方式保留该卷即可；重建镜像或容器不会丢失数据。
- `.env` 不提交到 Git，不复制到日志或文档。

## basePath 说明

默认站点前缀为 `/manage`，通过构建参数 `NEXT_PUBLIC_BASE_PATH` 决定：

```bash
docker build --build-arg NEXT_PUBLIC_BASE_PATH=/manage -t axhub:latest .
```

该值会被**静态内联**进代码（客户端与服务端都会替换为字面量），因此**构建后无法在运行期修改**；如需更换前缀必须重建镜像。`docker-compose.yml` 中的 `NEXT_PUBLIC_BASE_PATH` 仅用于健康检查拼接路径，需与构建参数保持一致。

与之相对，`NEXT_PUBLIC_BASE_URL` 不参与构建，是**运行期读取**的，用于生成分享与查看链接；更换内网地址时只改 `.env` 并重启容器即可，无需重建镜像。

## 本地开发与部署环境的地址配置

本地 `npm run dev` 使用 `next dev`，默认端口是 **3000**，与 Docker 部署的宿主端口（默认 3000，可设为其它值）可能不同，因此地址要分开配置：

- **本地开发**：新增 `.env.local` 覆盖，使分享 / 查看链接与开发端口一致：

  ```bash
  # .env.local
  NEXT_PUBLIC_BASE_URL=http://localhost:3000
  ```

  Next.js 的加载优先级是 `.env.local` > `.env`，且 `.env.local` 已被 `.gitignore`、`.dockerignore` 排除，**不影响服务器部署**。
- **服务器部署**：在 `.env` 中把 `NEXT_PUBLIC_BASE_URL` 设为内网实际地址（如 `http://192.168.1.100:3000`），`APP_HOST_PORT` 设为宿主机映射端口。

> 注意：`docker-compose` 只读取 `.env`（不读 `.env.local`），`next dev` 只在本机开发时读取两者。忽略此区分会导致开发环境里分享链接指向错误的端口。

## 不要用本地构建的产物部署

- `NEXT_PUBLIC_BASE_URL` 属于 `NEXT_PUBLIC_*`：**只要它在构建时存在，就会被静态内联成常量**。
- Docker 构建通过 `.dockerignore` 排除了所有 `.env*`（含 `.env.local`），所以镜像内该值保持**运行期读取**，更换内网地址无需重建。
- 但本地执行 `npm run build` 会加载 `.env.local`，把 `http://localhost:3000` 内联进产物。**切勿把本地 `npm run build` 的产物直接打包上服务器**，生产请始终使用 `docker build` 在容器内构建。

## 反向代理（可选）

如需通过 80/443 端口或域名访问，可在内网 Nginx / Caddy 上做反向代理。跨域部署时保持 `NEXT_PUBLIC_BASE_PATH` 与代理路径一致即可。

## 局域网提示

- 本方案默认不包含 HTTPS，适用于内网环境。
- 内网 HTTP 访问时保持 `COOKIE_SECURE=false`，否则浏览器会拒绝保存会话 Cookie，导致登录后无法跳转。
- 若启用 HTTPS，请将 `COOKIE_SECURE=true` 并更新 `NEXT_PUBLIC_BASE_URL` 为 `https://`。
